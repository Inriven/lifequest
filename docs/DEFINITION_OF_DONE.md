# LifeQuest — Definition of Done

Этот документ определяет, когда фича действительно готова. Принцип: «работает у меня» не считается Done.

## 0. Глобальный DoD для любой фичи

Фича считается Done, если одновременно выполнены все пункты:

### Product / UX
- Есть чёткая пользовательская задача (JTBD): зачем человек открывает эту фичу.
- Основное действие понятно без инструкции.
- Для основного действия не требуется лишний ручной ввод, если данные можно вывести/предложить автоматически.
- Есть empty state, loading state, error state, success state.
- Есть undo/отмена там, где пользователь может потерять данные или случайно совершить действие.
- На mobile основной сценарий выполняется одной рукой без обязательного desktop-only hover.
- Нет технических терминов, не нужных пользователю.
- Нет визуального шума, не несущего статуса/действия/прогресса.

### UI
- Проверено desktop 1440×900 и 1920×1080.
- Проверено mobile 390×844 и 360×800.
- Нет горизонтального скролла.
- Tap target основных контролов не меньше 44×44 px на mobile.
- Основной текст >= 16 px mobile; вспомогательный текст не превращается в микротекст.
- Все hover/focus/pressed/disabled состояния существуют.
- Иконки читаемы без декоративных контейнеров, если контейнер не несёт функцию.
- Контраст не теряется на всех активных фоновых темах.

### Motion / Sound
- Анимация сообщает состояние, а не задерживает пользователя.
- Микроанимации <= ~300 мс, если нет осознанной reward-сцены.
- Большие reward-анимации используются только для больших событий.
- Звук можно отключить глобально.
- Повторяющийся звук не раздражает при 20+ повторениях подряд.
- Для mobile предусмотрен haptic hook, если жест физически значимый.

### Data / Persistence
- Данные переживают reload.
- Если есть аккаунт, данные синхронизируются с сервером.
- Нет потери данных при повторном клике/сетевом retry.
- Серверные действия идемпотентны там, где это нужно.
- У пользователя нет доступа к данным другого пользователя.
- RLS включён для пользовательских таблиц Supabase.

### Engineering
- TypeScript без ошибок.
- Production build проходит.
- Нет console.error в happy path.
- Нет дублирующих источников истины для одного состояния.
- Нет dead code после завершения рефакторинга.
- Фича не добавляет CSS-hotfix слой поверх старого бага — исправляется первопричина.
- Критическая бизнес-логика покрыта unit/integration test или явно описанным acceptance test.

### Analytics
- Есть событие начала ключевого действия.
- Есть событие успешного завершения.
- Есть событие отмены/ошибки, если это важно для продуктового анализа.
- События не содержат чувствительный пользовательский текст без необходимости.

### Release
- Проверено в Vercel Preview.
- Проверено после hard refresh.
- Проверено в Chrome + mobile browser.
- Для критических фич проведён regression-check соседних сценариев.
- Только после этого merge в production.

---

# 1. App Shell / Navigation

Done, когда:
- Desktop sidebar фиксирован на 100dvh.
- Primary nav: Задачи / Статус / Путь / Артефакты / Handbook.
- Аккаунт и настройки не занимают primary tab: профиль расположен снизу sidebar.
- Hover/click профиля открывает flyout: Профиль / Достижения / Миры / Друзья / Настройки / Выход.
- На mobile primary nav превращается в bottom navigation из 5 пунктов.
- Нет ромбов/универсальных декоративных рамок вокруг sidebar icons.
- Active state заметнее hover state.
- Контент не прыгает при смене раздела.
- Scroll находится внутри content-area, а не двигает app shell.

# 2. Tasks / Today

Done, когда:
- При входе пользователь сразу понимает «что делать сейчас».
- Есть Main Quest и группированные задания.
- Группы сворачиваются/разворачиваются по клику.
- Collapse state сохраняется после reload.
- На mobile accordion не превращает экран в длинную простыню.
- Task можно отметить выполненной.
- Task можно открыть.
- Task можно запустить в Focus/Timer.
- Completion обновляет XP/связанный прогресс транзакционно.
- Просроченная задача предлагает перепланирование, а не «наказывает» пользователя.
- Пустой Today предлагает добавить/импортировать первое задание.

# 3. Quick Add / Inbox

Done, когда:
- Задача добавляется одной строкой.
- Natural language parser предлагает дату/время/проект/тип, но не заставляет подтверждать каждое поле.
- Пользователь может сохранить задачу за <= 2 действия после ввода.
- Неразобранное попадает в Inbox.
- AI suggestions отделены от подтверждённых данных.
- Есть undo после добавления.

# 4. Clock — выбор времени

Done, когда:
- Существует единое состояние времени; стрелки — только визуальное представление.
- Минутная стрелка меняет минуту и непрерывно двигает часовую.
- 10:59 → 11:00 двигает часовую вперёд без возврата в исходное положение.
- 11:00 → 10:55 при обратном вращении работает корректно.
- Переход 11:59 → 12:00 / 23:59 → 00:00 проверен.
- Есть snap по 5 минут.
- Каждый snap даёт короткий tick; 00/15/30/45 может иметь усиленный tok.
- Touch и mouse работают одинаково.
- Время можно также ввести точно цифровым способом.
- На mobile предусмотрен лёгкий haptic snap.

# 5. Timer

Done, когда:
- Timer и «время выполнения» разделены как разные режимы.
- Есть Start / Pause / Resume / Stop / Complete.
- Timer связан с конкретной task.
- После запуска timer отображается в topbar во всех разделах.
- Переход между страницами не сбрасывает timer.
- Reload не сбрасывает timer.
- Background/foreground пересчитывает остаток по timestamps, а не по количеству setInterval ticks.
- Timer никогда не уходит в отрицательное время.
- Завершение может закрыть task или вернуть пользователя в неё.
- Позже native Android notification может читать то же timer state без изменения модели данных.

# 6. Focus / Mission Mode

Done, когда:
- Остаётся одна текущая задача.
- Видны название, ожидаемый результат, timer и pause/complete.
- Остальная навигация визуально приглушена.
- Exit не теряет timer.
- После completion показывается reward соответствующей силы.
- Следующий квест предлагается, но не запускается без согласия.

# 7. Goals / AI Quest Path

Done, когда:
- AI сначала выявляет недостающий контекст, а не сразу генерирует 40 универсальных задач.
- Goal хранится отдельно от AI-generated plan.
- Plan имеет версии, чтобы пользователь мог откатить неудачную декомпозицию.
- Структура: Mission → Act → Chapter → Quest → optional Subquest.
- Зависимости между квестами валидируются.
- Есть estimated effort/time.
- Не создаётся невыполнимый дневной объём без предупреждения.
- Пользователь видит Next Best Quest.
- Можно создать Side Quest, не ломая основной путь.
- AI-текст преобразуется в язык интерфейса LifeQuest, а не показывается сырой простынёй.

# 8. Character / XP / Skills

Done, когда:
- XP нельзя накрутить простым кликом по skill.
- XP приходит из событий выполнения.
- Skill XP связан с конкретными задачами/действиями.
- Skill Level Up происходит только при достижении threshold.
- Есть история источников Skill XP.
- Full-screen Skill Up проигрывается один раз на реальное повышение.
- Повторный reload не воспроизводит одну и ту же reward-сцену бесконечно.
- Ранг вычисляется из прозрачной стабильной модели прогресса.

# 9. Handbook

Done, когда:
- Есть Daily Activity.
- Есть Weekly Activity.
- Есть Growth Path.
- Есть Season progress.
- Handbook отвечает на вопрос «что сейчас имеет смысл сделать».
- Не дублирует Today простым вторым списком задач.
- Награды привязаны к meaningful progress, а не фарму мелких действий.

# 10. Artifacts / Resource Graph

Done, когда:
- Пользователь не обязан вручную вести полный инвентарь.
- AI предлагает найденные ресурсы в отдельном review/inbox.
- Новый ресурс не становится «истиной», пока пользователь не подтвердил его или не сработало явно разрешённое правило.
- Ресурс имеет type: person/tool/asset/access/knowledge/device/etc.
- Система показывает, в каких квестах ресурс реально использовался.
- Рекомендации ресурсов к квесту имеют объяснимое основание.
- Удалённый/потерянный ресурс можно архивировать без потери истории.

# 11. Wishlist Capture

Done, когда:
- Пользователь может Share link → LifeQuest.
- Может загрузить screenshot/photo.
- AI извлекает title/image/price/store/link, где это возможно.
- Пользователь подтверждает результат одной карточкой.
- Ошибочное распознавание легко исправляется.
- Изображение товара не генерируется вместо реального, если есть оригинальное фото.
- Wishlist item можно связать с реальной целью/наградами.

# 12. Wishlist Reward Splash

Done, когда:
- Splash строится динамически из реального изображения и данных товара.
- Нет необходимости вручную делать баннер под каждую хотелку.
- Long title не ломает layout.
- Portrait/landscape product photos корректно вписываются.
- Есть fallback, если фото отсутствует.
- Анимация соответствует milestone, а не обычному task completion.

# 13. Crystals / Wishes / Economy

Done, когда:
- У каждой валюты одна понятная роль.
- XP = развитие; Skill XP = конкретный навык; Crystals = cosmetics; Wishes/Keys = редкие unlocks.
- Нельзя покупать реальный skill/rank за деньги.
- Не существует pay-to-win x2 XP.
- Реальные деньги не участвуют в случайном розыгрыше физических товаров в MVP.
- Все reward transactions журналируются и не дублируются при retry.

# 14. Worlds / Themes

Done, когда:
- Core layout и control semantics одинаковы во всех мирах.
- World меняет background, materials, accents, particles, audio pack, clock skin, reward visuals.
- Новый мир можно unlock-нуть milestone-событием.
- Glitch/world transition не проигрывается на каждом обычном входе.
- Старые unlock-нутые миры остаются доступны.
- Любой мир проходит contrast/readability check.

# 15. Profile / Premium Frames

Done, когда:
- Avatar и frame используют один центр и одну систему размеров.
- Frame не «ездит» на разных viewport.
- Без avatar есть корректный placeholder.
- Premium frame является cosmetic/status layer, а не функциональным преимуществом.
- В настройках нет dev-информации вроде имени шрифта/внутренней версии ассета.

# 16. Audio Manager

Done, когда:
- Все звуки вызываются через единый AudioManager.
- Есть semantic keys (`timer.tick`, `quest.complete`, `skill.levelup`).
- World/theme может подменить sound pack без переписывания компонентов.
- Есть master volume/mute.
- Одновременные события не создают неконтролируемый аудиоспам.
- Browser autoplay restrictions обработаны.

# 17. Auth / Supabase

Done, когда:
- Sign in / sign out работают.
- Session survives refresh.
- Все пользовательские таблицы имеют `user_id`.
- RLS запрещает доступ к чужим строкам.
- Storage policies ограничивают пользовательские файлы.
- Publishable key может находиться в frontend; service role key никогда не попадает в frontend.
- Security Advisor проверен после DDL.

# 18. Vercel Preview / Release

Done, когда:
- Каждый крупный change имеет preview URL.
- Build не зависит от локальных абсолютных путей.
- Environment variables разделены для preview/production.
- SPA routing работает после прямого открытия URL и refresh.
- Production deploy выполняется только после acceptance-check preview.

# 19. Android Readiness

Фича web считается Android-ready, если:
- Нет hover-only обязательных действий.
- Touch gestures имеют альтернативу.
- Safe areas учтены.
- Timer хранится timestamp-моделью.
- Notifications/haptics/share/camera вынесены за adapter interface.
- Не требуется переписывать core business logic при добавлении Capacitor.

# 20. Definition of Done спринта

Спринт закрыт, когда:
- Все заявленные acceptance criteria пройдены.
- P0 bugs = 0.
- P1 bugs либо 0, либо явно вынесены и согласованы.
- Preview build доступен.
- Проведён UX-pass desktop/mobile.
- Проведён code duplication/dead-code pass.
- Changelog обновлён.
- Следующий спринт не начинается поверх заведомо сломанного core.
